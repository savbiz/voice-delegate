# M8 — multi-process scaling reference

The supplied topology runs **two API processes, one separate worker service and an Nginx
gateway on one Docker host**. Audio remains browser-to-provider. This is a tested reference
for bounded process isolation, not a multi-region system or cross-host SQLite deployment.

## Ownership and admission

Each API has a fixed `VOICE_INSTANCE_ID` (`a` or `b`). New session IDs include that prefix;
the gateway routes subsequent operations to the owner. Every route still checks personal
invitation and session key. An ID alone grants nothing. Both APIs use one durable SQLite
volume: daily reservations and active session leases are admitted in one immediate
transaction. Global and per-user concurrent limits therefore apply across API processes.

Normal close releases the lease. After a crash, its absolute expiry is session TTL plus
connect/close budgets and three seconds. No quota refund occurs. Leases are removed at the
next admission after expiry. All instances must share identical budgets, invitations and
clock. SQLite requires a local filesystem with working locks; do not put this volume on
NFS or split it across hosts. Cross-host scaling requires a different shared admission store.

A live WebRTC connection cannot migrate between API processes. Owner failure makes its
session operations fail explicitly; restart does not resurrect the call or repeat tools.
Other owners remain usable. The user starts a new conversation after capacity is released;
there is no seamless audio failover across owner death. Unknown remote provider cleanup
remains unconfirmed after a crash. Nginx never retries a request against another owner.

## Separate worker and backpressure

`VOICE_WORKER_EXECUTION=remote` delegates to a private HTTP worker using a separate service
credential. The worker has finite active capacity and a finite ledger (defaults: 4 jobs,
128 records). It returns 429 before accepting excess work, with no unbounded waiting queue.
The API reports this as busy. A job has a preallocated UUID and a deadline of at most 120
seconds. Job creation is never retried. Duplicate IDs return their existing status; a reused
ID with a different body is rejected. Completed/cancelled records are retained for 180 seconds.
Cancellation creates a tombstone even if it arrives before creation. Running work receives
cancellation; late results are also suppressed by the existing API generation check.

Only the API can access job endpoints. Jobs hold bounded goal/context/result data in memory,
not logs or durable storage. Worker restart loses jobs: callers get failure, not replay.
This is bounded at-most-once submission, not an exactly-once guarantee through network
partitions or service restart. Only read-only tools are enabled. Keep the service private;
use HTTPS/mTLS if moving that HTTP hop outside the trusted host network.

## Running and testing

Configure personal invitations and a random `VOICE_WORKER_SERVICE_TOKEN` in a local env
file, then build and start with:

```bash
docker build -t voice-delegate:m8-candidate -f deployment/Dockerfile.backend .
docker compose --env-file .env -f deployment/scaling/compose.yaml up -d
```

The gateway binds localhost:18081. Place it behind the chosen HTTPS host before public use,
and update allowed hosts/origin in the Compose environment. The demo preserves one Uvicorn
worker per API and one per worker service. Do not run extra workers within those containers.
Use `VOICE_WORKER_MODE=openai` for the worker's paid planner; offline is the default.
Nginx applies an IP request rate limit, excludes authorization/body logging and bounds bodies.

Run the isolated, no-paid-call acceptance exercise:

```bash
uv run python scripts/scaling_smoke.py
```

It generates temporary invitations, uses the explicit scripted voice provider factory,
runs three rounds of eight concurrent sessions, checks overload and owner isolation,
forcibly kills API A, confirms API B still works, and restarts A. It removes only its own
containers and test quota volume. It never loads provider credentials. Reported p50/p95
measure fake-provider orchestration including polling, not audio latency or model quality.
The tests also verify cancellation tombstones, duplicate suppression and lease expiry.

Remaining deployment gates: real provider traffic at representative load, hosted TLS,
resource sizing, provider-side spending controls and a real listening test. No cross-host
high availability or transparent restoration of an interrupted audio stream is claimed.
