# M3 — Azure fallback candidate

The optional Azure GA Realtime adapter negotiates SDP on the server, attaches one bounded
sideband reader, maps function calls to the existing worker, and returns tool outputs.
Set `VOICE_FALLBACK_ENABLED=true`, `VOICE_AZURE_ENDPOINT=https://RESOURCE.openai.azure.com`,
`VOICE_AZURE_API_KEY`, `VOICE_AZURE_DEPLOYMENT` and `VOICE_AZURE_VOICE` on the backend.
The default remains GPT-Live with no fallback. Azure resources must already exist.

A provider stream failure retains the owned application session in `reconnecting` state.
The browser heartbeat detects this (up to ten seconds); media/data-channel failure also
initiates recovery. The browser closes the old peer and creates a new one. The authenticated
`POST /api/sessions/{id}/reconnect` takes SDP plus the current `generation`. Under the session
lock, the manager consumes the single attempt, cancels delegation, closes the old connection,
and connects Azure. Duplicate/stale requests return 409. Unsupported fallback returns 501.
There is no automatic retry of creation POSTs. Timeout consumes the attempt and removes the
session. Existing lifetime, heartbeat and capacity limits remain in force.

Only sealed text segments are replayed, bounded to twelve entries and 2048 tokens.
For Live, a change of speaker seals the previous segment; this is an approximation, not a
provider guarantee of completion. The current unfinished segment is omitted. Azure uses
completed transcripts. Tool calls, tool results and audio are never replayed. Replay is
conversation data, never system instructions. A user may need to repeat the last phrase.
Azure uses turn-based Realtime behavior; full-duplex Live behavior is not preserved.

Cleanup reports failure if either provider's finalization was unconfirmed. Azure uses its
GA call hangup endpoint. A lost creation response can still leave an unknown upstream call;
no subsequent request can reliably identify that call for cleanup.

Offline tests cover normalization, one-attempt concurrency, ownership, timeout, sealed replay
and cleanup after attach failure. Real Azure voice, microphone interruption, natural-language
delegation and fallback latency remain live release gates. No stable milestone tag is implied.
