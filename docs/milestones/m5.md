# M5 — controlled invitation demo

Enable `VOICE_PUBLIC_DEMO=true` with `VOICE_ENVIRONMENT=production`, a single HTTPS
`VOICE_ALLOWED_ORIGIN`, exact `VOICE_ALLOWED_HOSTS`, and `VOICE_INVITE_TOKENS` containing
a JSON object of stable pseudonymous user IDs to unique random tokens (at least 32 chars).
Generate each invitation locally with `python -c 'import secrets; print(secrets.token_urlsafe(32))'`.
Distribute invitations privately. Each invitation is a bearer credential, not a verified
human identity or an account login. Rotate/revoke by changing the mapping and restarting.
Keep the same user ID when rotating so daily reservations are retained.

All session operations require both the user's invitation and the session ownership key.
A different valid invitation cannot operate the session even if it knows its key.
Existing local/shared-code setups continue to work when public demo mode is disabled.

## Budgets

SQLite records reservations before admitting a session. Only hashes of stable user IDs,
UTC dates, counts and reserved seconds are stored. Tokens and transcripts are not stored.
Use one API process with a durable writable volume at `VOICE_QUOTA_DATABASE`.
Do not reset that volume when deploying or rolling back. A missing/read-only store fails
startup or admission; deleting the database deliberately resets budgets.

Limits include concurrent sessions per invitation, sessions/day, per-user seconds/day,
and global seconds/day. Each admission reserves the complete session TTL plus one second
for expiry sweep, doubled if Azure fallback is enabled. Reservations are not refunded,
even if connection fails or the user leaves early. This conservatively bounds admission
under ambiguous provider responses and persists across restarts. Day rollover is UTC;
active sessions can cross midnight. This is a reservation ledger, not provider billing.

`VOICE_MAX_DELEGATIONS_PER_SESSION` bounds worker invocations, each already constrained by
steps, completion tokens and timeout. The session allowance also bounds daily worker calls.
Provider pricing is not assumed. Remote cleanup failures or process crashes can cause
provider usage beyond local lifetime enforcement; configure provider-side budgets too.

`VOICE_DEMO_ENABLED=false` rejects new sessions with 503 after restart. Existing API close
and heartbeat routes retain authorization. Do not expose this minimal single-process demo
as a general multi-tenant production service. Add edge request-rate limits at the host.

## Deployment and rollback

Build an immutable image using `deployment/Dockerfile.backend`; run one worker behind HTTPS.
Mount persistent quota storage owned by UID 10001. Inject secrets through the hosting
provider's secret store, never frontend variables. `/healthz` verifies process health only.
Do not send authorization headers, .env contents, SDP or transcripts to access logs; the
application's OTel spans intentionally exclude those values. Avoid debug proxy/body logging.

Before public access, run identity isolation, quota exhaustion, close/expiry and rollback
checks on the actual host, then run real voice. Keep the prior image digest and deployment
configuration. Roll back the image while retaining the quota database and stable user IDs;
the ledger schema must remain compatible. Set the admission switch off if investigating
unexpected usage. Local container verification does not constitute a public deployment.

Acceptance remains pending a chosen public host, HTTPS, live voice and a hosted rollback
exercise. The repository now supplies the controls and automated tests, not a claim that
an internet-facing demo has already been published.
