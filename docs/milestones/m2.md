# M2 — delegated worker

M2 adds an actual LangGraph model/tool loop, `delegate_task(goal, context)`, asynchronous dispatch, finite context and result budgets, timeouts, duplicate suppression, and cancellation on interruption/close. The release candidate is `v0.1.0-m2-rc.1`. Live voice and a paid worker response still need an account smoke test before the full M2 release.

## Try it without an API key

From the repository root (the folder containing pyproject.toml):

```bash
uv sync --locked
uv run python -m voice_delegate.delegation.demo "calculate (120 + 80) * 1.22"
uv run python -m voice_delegate.delegation.demo "architecture"
```

The first result is `Offline worker result: 244`. This runs the real graph and calculator, with a deterministic planner. It is not a free language model. The offline planner accepts `calculate` or `calcola` followed by an arithmetic expression, and the exact topics `architecture`, `limits`, `delegation`. Other requests receive an honest unsupported response. The CLI always stays offline even if a provider key exists in the environment. The browser's Free demo remains a labeled scripted UI preview, not a backend invocation.

## Natural-language worker with live voice

Retain your existing `.env` and add:

```dotenv
VOICE_WORKER_MODE=openai
VOICE_WORKER_MODEL=gpt-4.1-mini
VOICE_WORKER_MAX_STEPS=4
VOICE_DELEGATION_TIMEOUT_SECONDS=15
VOICE_DELEGATION_RESULT_TOKENS=120
```

Set your personal `OPENAI_API_KEY` on the backend as for M1. Restart the backend and frontend with the existing commands. The text worker and live voice are separate billed model calls. Worker mode defaults to `offline`; enabling `openai` without a key fails configuration validation.

Try “Calcola il totale di 120 e 80 euro e aggiungi il 22 percento” or “Spiegami i limiti di questa architettura”. The worker has a calculator and three local reference notes. It cannot browse, book trips, send messages, or inspect external data. The text model can choose and sequence tools, subject to the step budget. Results are passed as commentary, never appended as trusted instructions.

## Control and cancellation

The event reader starts a background task and continues reading audio-related events and transcripts. A new delegation invalidates the old generation. Duplicate request IDs do not repeat work; at most 64 IDs are accepted per session. Global running worker tasks are capped at the session capacity, including cancellation cleanup. Busy requests receive a compact failure result, and excess lifetime delegation IDs set `request_limit` without dispatch.

The browser requests cancellation on microphone energy onset (three 20 ms samples above threshold, rearmed after 300 ms of silence). This is a simple VAD heuristic: noise/echo can cause false positives, quiet speech can be missed, and background tabs may delay timers. Echo cancellation is requested from the browser. Backend user-transcript fragments starting at or after a delegation's provider timestamp also invalidate its work. Older transcript fragments do not cancel it. Use **Cancel task** for an explicit cancellation request. **Stop** closes the whole conversation.

Cancellation invalidates the generation before canceling tasks. Results from workers that return after cancellation are discarded. A result already sent to the voice provider cannot be withdrawn by this application; no cancellation scheme can undo a completed external action. M2 tools are intentionally read-only. Local sync tools are tiny bounded operations; their executor threads may finish after cancellation. Future slow tools must cooperate with cancellation and apply their own deadlines.

Timeout limits how long a worker result is awaited. It cancels the worker and sends a short failure message. Provider transmission has its own two-second deadline, so result delivery is outside the worker execution budget. Noncooperative worker extensions continue occupying capacity until they actually finish; shutdown waits at most one additional second for them. Heartbeats report the last delegation status every ten seconds; this is not a low-latency status stream.

## Budgets

| Resource | Limit | Reason |
|---|---|---|
| Worker model steps | 4 by default, configurable 1–12 | Stop model/tool loops |
| Tools per model response | 1 | Keep execution and cancellation predictable |
| Worker duration | 15 seconds, configurable | Keep slow work finite |
| Delegated result | 120 o200k tokens by default, configurable 8–480 | Keep narration compact |
| Wire commentary | 500 UTF-8 bytes | Conservative independent guard for Live's documented 500-token append cap |
| Transcript context | 12 recent speaker segments, 2,048 o200k tokens | Bound retained context and prompt cost |
| Goal | Latest user segment, 512 o200k tokens | Bound dispatch input |
| Calculator | 160 characters, 40 AST nodes, finite results within ±1e12 | No code execution or expensive arithmetic |

Token clipping preserves valid Unicode and includes an ellipsis within the budget. The actual result must satisfy both token and byte budgets. o200k assets and their MIT license are bundled: first use of token counting works offline, without a tokenizer download. Transcript grouping is approximate, not a definitive turn detector. Corrections and incomplete transcripts can still require clarification. Failover history/replay remains M3.

## Protocol and tests

`docs/delegate_task.schema.json` is the application function schema. GPT-Live itself uses native client delegation; we do not send an invented tool schema to Live. Its event supplies an ID and timestamp, not a goal. The adapter saves the timestamp; the manager builds goal/context from bounded transcripts and maps the result to `session.commentary.append` with the original delegation ID.

The suite tests tool execution, unknown/unsafe requests, graph step limits, token/byte/Unicode bounds, timeout, worker failure redaction, ownership of the interrupt endpoint, duplicates, supersession, capacity, and suppression after interruption/close. Fake events validate orchestration; they cannot prove a voice model delegates appropriately.

Live release gate: with a key, confirm ordinary greetings do not delegate; a calculation delegates once and is narrated correctly; speaking over ongoing work cancels it without a late result; explicit cancellation and Stop release resources; configure a short timeout to verify an honest failure message. Record actual model/browser results before tagging the full M2 release. Provider acceptance is not proof that audio was played.

Public sources: [GPT-Live client delegation](https://developers.openai.com/api/docs/guides/live-delegation), [Live transcripts](https://developers.openai.com/api/docs/guides/live-conversations), [LangGraph graph/tool loop](https://docs.langchain.com/oss/python/langgraph/quickstart), [OpenAI tiktoken](https://github.com/openai/tiktoken).

## Candidate verification

Verified locally: 49 offline pytest tests, strict mypy, Ruff, uv/pnpm locked installs, both Python package builds, React/TypeScript build, three Vitest tests and three Playwright tests on Chromium 153. The text client can be constructed and closed without a network request. Paid model inference, real microphone interruption, Docker and cloud deployment have not been run for this candidate.
