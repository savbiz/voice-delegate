# M4 — observability and evaluation candidate

Application-owned OTel turn spans now parent provider transcript, delegation and fallback
spans. Metrics cover provider setup, fallback and worker outcomes, transcript arrival wait
and pending-worker cancellation. Export is opt-in; all labels are bounded and carry no
conversation text or ownership secrets. See [monitoring setup](../observability/README.md).

The local Compose stack includes an OTLP collector, Prometheus, and a provisioned Grafana
dashboard. Trace output is available in collector logs. The local stack was started on 2026-09-20: a fake-provider turn exported OTLP traces
and metrics, Prometheus returned provider/worker counters, and Grafana loaded all four panels.

The [offline evaluation suite](../evals/README.md) separates deterministic orchestration
checks from live model quality and acoustic latency. The browser fallback test checks that
recovery creates a new peer, retains session ownership and consumes only one attempt.

Candidate validation on 2026-09-20:
- Ruff lint/format and strict mypy.
- 62 offline pytest checks including evaluation fixtures and in-memory OTel verification.
- TypeScript/build, 3 Vitest checks and 4 Playwright Chromium checks.
- Python workspace package builds and Compose configuration validation.

Release gates still pending: paid Live/Azure validation, actual microphone/speaker checks,
and a recorded demonstration. No fabricated
latency scores or stable release tag are supplied. This completes the M1–M4 implementation
roadmap as a candidate; future v0.2 ideas remain outside that roadmap.
