# M6 — documentation questions with inspectable sources

The Documentation tab searches a bundled, reviewed snapshot of the project's public
Markdown documentation. It requires the same invitation as voice on gated deployments,
but uses no microphone or paid model and does not consume a voice session reservation.
Enter a project question, inspect the matching excerpts, and open each source card to
see its document path, section and snapshot ID. Unknown topics explicitly return no evidence.

The worker also exposes `search_documentation(query)` to the paid planner. The offline
planner accepts `docs fallback history` or `documentazione limiti sessioni`. It returns a
labeled excerpt, not an AI-generated answer. Natural-language synthesis requires the paid
planner and remains a live evaluation gate. Both use exactly the same retrieval corpus.

Source IDs derive from SHA-256 of document path, section and exact excerpt. Source text is
limited to 1600 characters per entry; queries to 500 characters; results to three sources.
Retrieval is lexical with a small Italian/English synonym map. It is not semantic search,
web browsing, or a claim that every relevant document is returned. A question outside the
corpus may require rephrasing or return no matches. Documentation describes defaults and
architecture; it does not inspect live settings or account state.

The model receives evidence as untrusted tool data. Citations come from the retrieval
result, not arbitrary model URLs. They travel separately from the bounded spoken result
and are shown by the browser heartbeat. Interruption invalidates them with the task
result. A citation means consulted evidence, not an automated proof of every model claim.
The source cards show the full selected excerpt for review. No user-provided URL or local
file path is fetched; no external write-capable tool is added.

## Refreshing the snapshot

Run `python scripts/build_reference.py` after reviewing changes to the four configured
source files, then commit the generated JSON. Offline tests verify every source excerpt
is present in its original file and its digest is correct. The corpus ships inside the
agent wheel and backend Docker image. Nothing is downloaded at query time.

## Verification

Tests cover source integrity, retrieval of history limits, explicit missing evidence,
authentication, source inspection, no voice creation, worker citations despite spoken
truncation, cancellation invalidation, and browser source cards. Public hosting and real
voice narration of a documentation answer remain acceptance gates; the local text workflow
can be exercised immediately with an API and frontend running.

Local container acceptance was also verified: non-root startup, personal authentication,
packaged source retrieval and quota persistence after restart. Reproduce with:

```bash
docker build -t voice-delegate:m6-candidate -f deployment/Dockerfile.backend .
uv run python scripts/smoke_container.py
```

The script uses a temporary container and generated test invitation on localhost:18080,
then removes the container. It does not load provider credentials or make paid calls.
